## Επισκόπηση της επεκτασιμότητας του YARP

Υπάρχουν 2 βασικά στυλ επεκτασιμότητας για το YARP, ανάλογα με τη συμπεριφορά δρομολόγησης που επιθυμείτε:

- Pipeline ενδιάμεσου λογισμικού (Middleware Pipeline)
- HTTP Forwarder

## Pipeline ενδιάμεσου λογισμικού

Το YARP χρησιμοποιεί την έννοια των διαδρομών (Routes), των clusters και των προορισμών (Destinations). Αυτά μπορούν να παρέχονται μέσω αρχείων διαμόρφωσης ή απευθείας μέσω κώδικα. Με βάση τους κανόνες δρομολόγησης, το YARP επιλέγει ένα cluster και απαριθμεί τους πιθανούς προορισμούς. Στη συνέχεια, χρησιμοποιεί το pipeline ενδιάμεσου λογισμικού για να επιλέξει τον προορισμό με βάση την υγεία του προορισμού, τη συνάφεια συνεδρίας, την εξισορρόπηση φορτίου κ.λπ.

Το μεγαλύτερο μέρος του προκατασκευασμένου pipeline μπορεί να προσαρμοστεί μέσω κώδικα:

- Πάροχοι διαμόρφωσης (Configuration Providers)
- Απαρίθμηση προορισμών (Destination Enumeration)
- Συνάφεια συνεδρίας (Session Affinity)
- Εξισορρόπηση φορτίου (Load Balancing)
- Έλεγχοι υγείας (Health Checks)
- Μετασχηματισμοί αιτημάτων (Request Transforms)
- Διαμόρφωση HttpClient (HttpClient configuration)

Μπορείτε επίσης να αλλάξετε τον ορισμό του pipeline ώστε να αντικαταστήσετε modules με τις δικές σας υλοποιήσεις, ή να προσθέσετε επιπλέον modules όπως χρειάζεται. Για περισσότερες πληροφορίες, δείτε το Ενδιάμεσο λογισμικό.

## HTTP Forwarder

Αν το pipeline του YARP είναι πολύ άκαμπτο για τη δική σας περίπτωση χρήσης, ή αν η κλίμακα των κανόνων δρομολόγησης και των προορισμών δεν είναι κατάλληλη για φόρτωση στη μνήμη, τότε μπορείτε να υλοποιήσετε τη δική σας λογική δρομολόγησης και να χρησιμοποιήσετε το HTTP Forwarder για να κατευθύνετε τα αιτήματα στον προορισμό της επιλογής σας. Το component `HttpForwarder` λαμβάνει το HTTP context και προωθεί το αίτημα στον παρεχόμενο προορισμό.

Το component μετασχηματισμού μπορεί ακόμα να χρησιμοποιηθεί όταν χρειάζεται ο forwarder. Για περισσότερες πληροφορίες, δείτε το Απευθείας προώθηση.
