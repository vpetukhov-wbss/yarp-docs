#Overview of YARP

Yet Another Reverse Proxy — a highly customizable reverse proxy library for .NET. Robust, flexible, scalable, secure. Runs inside the ASP.NET Core process you already ship.

introduction

YARP helps you build reverse proxy solutions tailored to your own needs, in plain C#. It sits between clients and backend servers — forwarding requests to the right destination and relaying the response back — the same role nginx or Envoy play, but as a library, not a separate process to operate.

what a reverse proxy does

A reverse proxy earns its place in the request path:

  • Routing — directs requests by URL pattern or header. /images, /api, and /db each land on a different cluster.
  • Load balancing — spreads traffic across backend instances so no single one gets overloaded.
  • Scalability — destinations scale up or down without the client noticing.
  • TLS termination — encryption ends at the proxy; backends stay simpler.
  • Security — internal endpoints never face the public internet directly.

how a reverse proxy handles http

Inbound connections terminate at the proxy. Pooled, reused connections carry outbound requests to destinations. YARP matches the request against configured routes, forwards it — transforming path and headers as needed — and streams the backend's response back to the caller.

Program.cs

C#// register the proxy, load routes + clusters from config
var builder = WebApplication.CreateBuilder(args);

builder.Services.AddReverseProxy()
    .LoadFromConfig(builder.Configuration.GetSection("ReverseProxy"));

var app = builder.Build();
app.MapReverseProxy();
app.Run();

note

Config reloads live — no restart needed. Use configuration filters to modify it during the load sequence.

why choose yarp

Built on ASP.NET Core, so extensibility means writing C#, not learning a proxy-specific DSL. Actively maintained by Microsoft; YARP and its docs are both open source.
