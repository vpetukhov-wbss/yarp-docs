§1Overview of YARP

Yet Another Reverse Proxy is a highly customizable reverse proxy library for .NET, designed to be robust, flexible, scalable, secure, and easy to use.1

1.1Introduction

YARP helps developers create powerful and efficient reverse proxy solutions tailored to their specific needs. It sits between client devices and backend servers, forwarding client requests to the appropriate destination and returning the response — the role long played by nginx or Envoy, offered here as a library hosted inside your own ASP.NET Core process rather than a separate piece of infrastructure to operate.

1.2What a reverse proxy does

A reverse proxy earns its place in the request path through several distinct benefits:

  • Routing. Directs requests to different backend servers based on predefined rules — URL patterns or request headers. /images, /api, and /db may each be routed to a different server.
  • Load balancing. Distributes incoming traffic across multiple backend servers, increasing performance and reliability.
  • Scalability. Backend servers may be added or removed without impacting the client.
  • TLS termination. Offloads encryption and decryption from backend servers, reducing their workload.
  • Security. Internal service endpoints stay hidden from external exposure.

1.3How a reverse proxy handles HTTP

Inbound connections are terminated at the proxy; pooled, reusable connections carry outbound requests to destinations. YARP matches the request against configured routing rules, forwards it to the appropriate cluster — transforming the path and headers where necessary — and relays the destination's response back to the caller.

Figure 1.1 — Registering the proxy
C#using Microsoft.AspNetCore.Builder;
using Microsoft.Extensions.DependencyInjection;

var builder = WebApplication.CreateBuilder(args);

builder.Services.AddReverseProxy()
    .LoadFromConfig(builder.Configuration.GetSection("ReverseProxy"));

var app = builder.Build();
app.MapReverseProxy();
app.Run();

Marginal note

Configuration reloads automatically when its source changes — no restart is required. See Chapter 4, Configuration filters, to modify configuration during the load sequence.

1.4Why choose YARP over other proxies

YARP is built on ASP.NET Core, integrating directly with the .NET ecosystem it was written for. Its extensibility points are exercised in ordinary C#, not a proxy-specific configuration language — a distinction that matters most once a deployment outgrows its defaults. It is actively maintained by Microsoft, and both YARP and this documentation remain open source.
